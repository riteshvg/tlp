Deterministic ID in Adobe Experience Platform

Deterministic ID refers to a non-random, predictable method of generating or linking identities based on consistent input data. In AEP, deterministic ID matching is used in several key contexts:

1. ECID Generation with Deterministic Linking

The Edge Network uses deterministic algorithms to link ECIDs (Experience Cloud IDs) and Demdex IDs:

| Priority | Source | Behavior |

| --- | --- | --- |

| 1 | Demdex ID | If a Demdex ID is present, the ECID is seeded from it, producing a consistent ECID across domains sharing the same third-party cookie. |

| 2 | FPID | If no Demdex ID exists but an FPID (First-Party Device ID) is present, the ECID is seeded from the FPID and a Demdex ID is derived from it. |

| 3 | Random | If neither exists, a new random ECID is generated and a Demdex ID is derived from it. |

Key Point: ECIDs and Demdex IDs are cryptographically linked through a deterministic algorithm, meaning one can be derived from the other. This enables:

  • Translation between first-party and third-party identity contexts without separate visitor handling logic
  • Audience activation through third-party infrastructure using corresponding Demdex IDs
  • Automatic linking of first-party identities to third-party contexts when browsers support third-party cookies

2. B2B Entity Resolution (Accounts & Opportunities)

As part of AEP's architecture upgrade, Adobe introduced deterministic ID matching for B2B entity resolution:

Before: If an account's DUNS number was updated in your CRM, the account ID would be linked to both the old and new DUNS numbers (historical approach).

After: With deterministic ID matching based on the latest data, the account ID is linked only to the new DUNS number, reflecting the current state more accurately.

How it works:

  • Accounts are entity resolved using the `b2b_account` namespace
  • Opportunities are entity resolved using the `b2b_opportunity` namespace
  • Resolution uses time-precedence based merging — the most recent data takes priority
  • Entity resolution jobs run daily during batch segmentation, prior to evaluating multi-entity audiences with B2B attributes
  • All other entities are unified with primary identity overlaps merged using time-precedence

Benefits:

  • Improved accuracy and consistency of account and opportunity data
  • More reliable segmentation, activation, and analytics for B2B use cases
  • You can view the latest merge profiles using the Profile Access APIs once daily jobs complete

3. When to Use Deterministic IDs

Deterministic IDs are ideal when you:

  • Have consistent, reliable identifying data (like DUNS numbers, customer IDs, email addresses)
  • Need predictable, reproducible identity resolution
  • Want to avoid random ID generation that could fragment customer profiles
  • Require stable cross-domain identity tracking

In summary: Deterministic ID in AEP ensures identities are resolved based on consistent, predictable logic rather than randomness, enabling accurate identity matching, profile unification, and reliable cross-channel activation.
