What the Retrieved Context Confirms

1. Web SDK, Mobile SDK, and Edge Network API are the supported data collection methods for AEP-based destinations including CDP and personalization destinations.

2. XDM is the core standardization framework — all customer experience data should conform to XDM schemas for downstream use in segmentation, personalization, and activation.

3. For attribute-based personalization (beyond audience membership), the Edge Network API with authenticated server-side integration is required — Web SDK and Mobile SDK alone only support audience-membership-based personalization.

4. XDM best practices recommend using pre-defined field groups (e.g., `AEP Web SDK ExperienceEvent`, `Consumer Experience Event`) and a product-agnostic naming model, with custom field groups only for org-specific data that doesn't fit existing structures.

General Guidance Based on XDM Design Principles (flagged as advisory, not doc-sourced)

Since XDM underpins everything, the architectural implications are worth noting:

| Approach | Pros | Cons |

|---|---|---|

| Preserve original language in XDM fields | Authentic data; supports locale-based segmentation; respects user intent | Requires locale-aware segment rules; analytics/reporting complexity |

| Translate to English before ingestion | Simplified downstream processing; unified audience logic | Loss of original signal; translation errors affect data quality; compliance risk |

For CDP use cases specifically, preserving the original language alongside a `locale` or `language` field (e.g., `xdm.environment.language` or a custom field group attribute) is generally the more robust approach because:

  • Audience segmentation can be built around `locale` as a profile attribute
  • Personalization via AJO or Adobe Target can key off `preferredLanguage` profile attributes
  • Translation at ingestion is a destructive, irreversible operation on the raw data

However, I strongly recommend validating this against official AEP/CDP schema documentation on Experience League, as Adobe may have specific field group recommendations for locale and language handling that were not included in the retrieved context for this query.
