Edge Profiles in Adobe Experience Platform

What Are Edge Profiles?

Edge profiles are lightweight profiles distributed throughout the Edge Network that serve as the preferred option for real-time, time-sensitive use cases. While Real-Time Customer Profile is the single source of truth for all profile data (sitting in a central hub), edge profiles enable fast, real-time personalization use cases.

Adobe applications like Adobe Target, Custom Personalization Destination, and Adobe Campaign use edges to provide personalized customer experiences in real-time.

How Data is Routed to the Edge

  • Data is routed to an edge by a projection
  • A projection destination defines which edge the data will be sent to
  • You need an Active-On-Edge merge policy to ensure edge profiles use the correct profile data

Key Use Cases

  • Real-Time Personalization: Quickly retrieve profile information from the edge profile to personalize a user's experience on your website
  • Customer Support: Retrieve profile information in real-time when a customer calls a support center agent

How to Ingest Data into Edge Profiles

Prerequisites / Components Required

| Component | Purpose |

|---|---|

| Datastreams | Receives incoming event data from Web SDK and responds with edge profile data |

| Merge Policies | Create an Active-On-Edge merge policy to ensure correct profile data is used |

| Custom Personalization Connection | Sends profile attributes to the Edge Network |

| Edge Network API | Used for real-time retrieval of profile attributes via interactive data collection |

Ingestion Steps

1. Configure a Datastream to receive Web SDK event data

2. Set up an Active-On-Edge merge policy in the segmentation UI

3. Configure a Custom Personalization connection to send profile attributes to the Edge Network

4. Use the Edge Network API interactive data collection endpoint to retrieve or push profile attributes in real-time

Audience Manager Data Latency to Edge (Reference)

If ingesting from Audience Manager, be aware of the following latency windows:

| Data Type | Type | Latency |

|---|---|---|

| Real-time data | Events | < 25 minutes (from Audience Manager Edge node to data lake) |

| Real-time data | Profile updates | < 10 minutes (to land in Real-Time Customer Profile) |

| Real-time + onboarded data | Profile updates | 24 to 36 hours (from DCS/PCS Edge + onboarded data to appearing in Real-Time Customer Profile) |

> Note: The 24–36 hour path for real-time + onboarded data does not land in the data lake directly. A Profile toggle can be enabled on Audience Manager Profile datasets to ingest this data directly into Real-Time Customer Profile.

How to Validate Edge Profiles

Using Adobe Experience Platform Assurance — Edge Delivery View

The Edge Delivery view inside Adobe Experience Platform Assurance allows you to:

  • Inspect and validate AJO Inbound edge delivery of messages to your web and mobile apps
  • Troubleshoot the delivery of AJO Inbound web and mobile campaigns and journeys

Validation Steps

1. Open Adobe Experience Platform Assurance

2. Navigate to the Edge Delivery view

3. Connect your web or mobile session

4. Inspect the edge delivery events to confirm profile data is being correctly projected and served at the edge

Edge Segmentation (Related Capability)

Edge segmentation allows you to evaluate audiences instantaneously on the edge, enabling:

  • Same-page personalization
  • Next-page personalization

This works in conjunction with edge profiles to deliver real-time audience membership decisions without round-tripping to the central hub.

Limitations

Based on the retrieved documentation, the following limitations are noted:

1. Audience Manager onboarded data (24–36 hr path) does not land in the data lake directly — it only goes to Real-Time Customer Profile unless the Profile toggle is explicitly enabled

2. Edge profiles are lightweight — they are not a full replacement for the comprehensive Real-Time Customer Profile hub; they are optimized for speed, not completeness

3. Edge profiles rely on correct merge policy configuration (Active-On-Edge) — incorrect merge policy setup will result in wrong data being served

4. Projection destinations must be properly configured to route data to the correct edge region

> ⚠️ The retrieved documentation does not cover all exhaustive guardrails and limits (such as attribute count limits, storage size, or TTL on edge). For complete performance guardrails, refer to the Performance guardrails section of the Edge Profile documentation on Adobe Experience League.
