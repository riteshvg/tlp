How do i validate if Edge is enabled in my AEP sandbox

Based on the retrieved documentation context available to me, I don't have specific step-by-step documentation on a dedicated "Edge enablement validation" feature within AEP sandbox settings.

However, based on my knowledge of the Adobe Experience Platform and Data Collection ecosystem, here are the key areas where you can validate Edge is enabled and functioning in your AEP sandbox:

1. Validate via Datastream Configuration

Prerequisites: Access to Adobe Experience Platform Data Collection UI

1. Navigate to Adobe Experience Platform Data Collection → Datastreams

2. Select your Datastream tied to your sandbox

3. Confirm the following services are enabled:

  • Adobe Experience Platform service is toggled ON
  • Edge Segmentation toggle is enabled
  • Personalization Destinations (if applicable) are configured

4. Confirm the correct sandbox is mapped to the Datastream

2. Validate Edge Segmentation is Enabled on Segment Definitions

1. Navigate to AEP → Segmentation → Segments

2. Open a specific segment definition

3. Under Evaluation Methods, check if Edge Segmentation is listed as enabled

4. In the API response, look for:

```json

"evaluationInfo": {

"synchronous": {

"enabled": true

}

}

```

This confirms edge (synchronous) evaluation is active for that segment.

3. Validate via Adobe Experience Platform Debugger

1. Install the Adobe Experience Platform Debugger Chrome extension

2. Navigate to your website or property

3. Open the Debugger and check:

  • Edge Network requests are firing to `edge.adobedc.net`
  • Datastream ID is correctly referenced in the request
  • Identity stitching (ECID) is present in the Edge request payload

4. Under the AEP section of the debugger, confirm:

  • Responses include handle payloads (e.g., `identity:result`, `personalization:decisions`)

4. Validate Edge Profile via API

You can query the Edge Profile directly using the AEP Profile Lookup API:

```http

GET /entities?schema.name=_xdm.context.profile&entityId={ECID}&entityIdNS=ECID

```

  • A successful response with profile attributes confirms the profile is being projected to Edge
  • If no Edge profile exists, the profile may not yet be projected or the Datastream may not be correctly configured

5. Validate Merge Policy for Edge

1. Navigate to AEP → Profiles → Merge Policies

2. Confirm the Active-On-Edge Merge Policy is set and enabled for your sandbox

3. The active-on-edge merge policy determines which profile attributes are projected to Edge

Summary Checklist

| Validation Area | What to Check |

|---|---|

| Datastream | AEP service enabled, correct sandbox mapped |

| Segment Definitions | Edge segmentation toggle enabled |

| AEP Debugger | Edge Network requests firing, handle payloads returned |

| Profile API | Edge profile attributes returned on lookup |

| Merge Policy | Active-on-Edge merge policy configured |

If any of these checks fail, that would indicate Edge is either not fully configured or not enabled for your specific sandbox. I'd recommend verifying each area systematically.
