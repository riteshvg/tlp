Building AEP Schemas from Adobe Analytics eVar & Prop Data

Understanding the Context

eVars and props are Adobe Analytics-specific constructs (custom variables). When bringing this data into Adobe Experience Platform (AEP), you need to map and translate these variables into XDM (Experience Data Model) schema fields. AEP does not natively understand "eVar1" or "prop5" — you must represent them meaningfully in XDM.

Which Schema to Use?

For Adobe Analytics data flowing into AEP, you should use the Adobe Analytics ExperienceEvent Template schema, which is built on:

| Schema Class | Field Group to Add |

|---|---|

| XDM ExperienceEvent (primary class) | Adobe Analytics ExperienceEvent Full Extension |

| XDM ExperienceEvent | Adobe Experience Platform Web/Mobile SDK fields (if applicable) |

The XDM ExperienceEvent class is the correct base class because:

  • eVars and props are event-level data (captured per hit/event)
  • ExperienceEvent tracks timestamped behavioral data
  • It aligns with how Analytics collects hit data

Schema Composition Concepts You Need to Know

A schema in AEP is built from building blocks:

  • Class → Defines the behavioral type of data (ExperienceEvent or Individual Profile)
  • Field Groups → Reusable sets of fields added to the schema
  • Data Types → Reusable field structures used within field groups
  • Fields → Individual attributes

Step-by-Step Process

Prerequisites

  • Access to Adobe Experience Platform with Schema Editor permissions
  • A mapping document listing all eVars/props and their business meaning (e.g., eVar1 = Campaign Name, prop5 = Page Name)

Step 1: Document Your eVar/Prop Mapping

Before building anything, create a mapping table:

| Analytics Variable | Business Name | Data Type | Example Value |

|---|---|---|---|

| eVar1 | Campaign Name | String | "Summer_Sale_2024" |

| eVar2 | Product Category | String | "Electronics" |

| prop1 | Page Name | String | "Home Page" |

| prop3 | Search Term | String | "running shoes" |

Step 2: Create a New Schema in AEP

1. Navigate to Adobe Experience Platform → Data Management → Schemas

2. Click Create Schema

3. Select XDM ExperienceEvent as the base class

4. Give your schema a meaningful name (e.g., `Analytics Hit Data - eVar Props Schema`)

Step 3: Add the Adobe Analytics Field Group (for raw Analytics data ingestion)

If you are ingesting raw Adobe Analytics data via the Analytics Source Connector:

1. In the schema editor, click Add under Field Groups

2. Search for and add Adobe Analytics ExperienceEvent Full Extension

  • This field group contains pre-built fields for `evar1–evar250` and `prop1–prop75` under the `_experience.analytics.customDimensions` path

3. This allows the Analytics Source Connector to auto-map eVars and props into XDM

Step 4: Add Custom Field Groups for Semantic Meaning (Best Practice)

Raw eVar/prop field names are not human-readable. It is best practice to also create a custom field group with meaningful field names:

1. In the schema editor, click Add → Create New Field Group

2. Name it (e.g., `Custom Analytics Variables`)

3. Add fields with business-meaningful names:

  • `campaignName` (String) → maps from eVar1
  • `productCategory` (String) → maps from eVar2
  • `pageName` (String) → maps from prop1
  • `searchTerm` (String) → maps from prop3

4. Save the field group and add it to your schema

Step 5: Define the Primary Identity

1. Identify your visitor identity field (e.g., ECID, CRM ID)

2. In the schema, select that field and toggle Identity → mark as Primary Identity

3. Assign the correct Identity Namespace (e.g., `ECID`)

> ⚠️ A primary identity is required for the schema to be enabled for Real-Time Customer Profile.

Step 6: Enable Schema for Real-Time Customer Profile (Optional but Recommended)

1. In the schema editor, toggle Profile switch at the top right

2. Confirm the prompt — this makes data from this schema contribute to unified profiles

Step 7: Data Ingestion & Mapping

Depending on your data source:

| Ingestion Method | Mapping Approach |

|---|---|

| Analytics Source Connector | Auto-maps eVars/props to `_experience.analytics.customDimensions.eVars.eVar1` etc. |

| Batch Ingestion (CSV/JSON) | Use Data Prep (Mapper) to manually map eVar columns to XDM fields |

| Web SDK / Tags | Map eVars/props in the Data Element and Data Stream mapping rules |

| HTTP API / Streaming | POST XDM-formatted JSON directly with fields mapped |

Step 8: Validate the Schema

1. Use the Schema Editor preview to confirm all fields are correctly defined

2. Use Data Prep to validate field mappings before ingestion

3. After ingestion, check Datasets → Data Activity to confirm records landed correctly

Summary Flow

```

eVar/Prop Data

↓

Document Business Meaning (Mapping Doc)

↓

Create XDM ExperienceEvent Schema

↓

Add Analytics ExperienceEvent Full Extension Field Group

↓

Add Custom Field Group (Semantic Names)

↓

Set Primary Identity + Enable Profile

↓

Ingest via Source Connector / Batch / Web SDK

↓

Validate in AEP Datasets

```

Key Takeaway

> The XDM ExperienceEvent class with the Adobe Analytics ExperienceEvent Full Extension field group is the recommended schema for eVar/prop data. Always pair it with a custom field group that gives business-meaningful names to your variables for downstream usability in CJA, AJO, and Real-Time CDP.
