Building a Schema in Adobe Experience Platform Using Postman

Based on the retrieved documentation, here is a step-by-step walkthrough for building a schema using Postman.

Step 1: Authenticate — Get Your Access Token

Before building anything, you need a valid access token.

1. In Postman, ensure your Environment is selected in the top-right dropdown (it should be named something like `--aepUserLdap-- OAuth Credential`)

2. In the Adobe IO - OAuth collection, select the request named POST - Get Access Token

3. Click Send

4. In the Body section of the response, you should see:

| Key | Value |

|---|---|

| `token_type` | `bearer` |

| `access_token` | `eyJhbGciOiJSU...` (long token string) |

| `expires_in` | `86399` (valid for 24 hours) |

> Important: This token is valid for 24 hours only. After expiry, re-run this request to generate a new one before making any further API calls.

Step 2: Import the Schema Registry API Collection

1. Go to the Experience Platform Postman Samples on GitHub

2. Download the Schema Registry API collection JSON file to your local folder

3. In Postman, click File > Import

4. Select the downloaded file and click Import

5. Confirm the import when prompted

Step 3: Verify Your Setup — List Existing Schemas

Before creating a schema, confirm everything is working:

1. Open Schema Registry API > Schemas > List schemas

2. Check the Params and Headers tabs — they should reference your environment variables automatically

3. Confirm the Headers > Accept value is set to:

```

application/vnd.adobe.xed-id+json

```

4. Click Send

5. A successful `200 OK` response returns a list of available XDM schemas

Step 4: Configure the Create Schema Request

Set the Request Type and URL

1. In Postman, create a new request or locate Create schema in the Schema Registry API collection

2. Set the method to POST

3. Set the URL to:

```

https://platform.adobe.io/data/foundation/schemaregistry/tenant/schemas

```

Set the Headers

Go to the Headers tab and add the following:

| Key | Value |

|---|---|

| `Authorization` | `Bearer {{ACCESS_TOKEN}}` |

| `Content-Type` | `application/json` |

| `x-api-key` | `{{API_KEY}}` |

| `x-gw-ims-org-id` | `{{ORG_ID}}` |

| `x-sandbox-name` | `{{SANDBOX_NAME}}` |

> The double curly braces `{{ }}` automatically pull values from your active Postman environment.

Set the Request Body

1. Go to the Body tab

2. Select raw and choose JSON from the dropdown

3. Enter your schema definition — choose the right class for your use case:

For a Profile Schema (customer attributes):

```json

{

"title": "My Customer Profile Schema",

"description": "Stores customer attribute data.",

"type": "object",

"allOf": [

{

"$ref": "https://ns.adobe.com/xdm/context/profile"

},

{

"$ref": "https://ns.adobe.com/xdm/context/profile-person-details"

},

{

"$ref": "https://ns.adobe.com/xdm/context/profile-personal-details"

}

]

}

```

For an ExperienceEvent Schema (behavioral/time-series data):

```json

{

"title": "My Experience Event Schema",

"description": "Tracks behavioral event data.",

"type": "object",

"allOf": [

{

"$ref": "https://ns.adobe.com/xdm/context/experienceevent"

},

{

"$ref": "https://ns.adobe.com/xdm/context/experienceevent-person"

}

]

}

```

Step 5: Send the Request and Review the Response

1. Click Send

2. A successful response returns HTTP 201 Created with the full schema definition, including a unique `$id` — save this value, you will need it to reference the schema later

Step 6: (Alternative) Upload a Schema from a JSON File

If you already have a schema defined as a JSON file, you can upload it directly:

1. Set the method to POST

2. Set the URL to:

```

https://platform.adobe.io/data/foundation/conversion/schemas/upload

```

3. Go to the Body tab and select form-data

4. Add a key named `file`, change its type to File, and select your `.json` file

5. Click Send

A successful response looks like:

```json

{

"id": "292add3716daffabf14b14259afc8fab",

"version": 0,

"jsonSchema": {

"id": "string",

"firstName": "string",

"lastName": "string"

}

}

```

Schema Building Reference

Key Schema Classes

| Use Case | Class |

|---|---|

| Customer profile data | `XDM Individual Profile` |

| Behavioral / event data | `XDM ExperienceEvent` |

Schema Components

| Component | Description |

|---|---|

| Class | Defines base behavior — record (Profile) or time-series (ExperienceEvent) |

| Field Groups | Reusable sets of fields added to extend the schema |

| Data Types | Reusable objects used across schemas regardless of class |

| Fields | Lowest-level elements with a name and a data type |

Troubleshooting

| Error | Likely Cause | Fix |

|---|---|---|

| `401 Unauthorized` | Expired access token | Re-run POST - Get Access Token |

| `403 Forbidden` | Insufficient permissions | Check API key permissions in Adobe Developer Console |

| `400 Bad Request` | Malformed JSON body | Validate your JSON syntax and `$ref` values |

| `404 Not Found` | Wrong sandbox name | Verify `SANDBOX_NAME` in your environment variables |
