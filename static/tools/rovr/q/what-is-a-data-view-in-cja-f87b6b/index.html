What is a Data View in CJA?

Definition

A data view is a container specific to Customer Journey Analytics that lets you determine how to interpret data from a connection. It specifies all dimensions and metrics available in Analysis Workspace and which columns those dimensions and metrics obtain their data from.

Data views are defined in preparation for reporting in Analysis Workspace and are similar to Virtual Report Suites in Adobe Analytics.

Core Purpose

Data views allow you to configure the data that comes into CJA so that it can be most useful for your reporting and analysis.

▶ Watch: Data Views Overview

Key Characteristics

Non-Destructive

  • Any settings you select or change in a data view are retroactive and non-destructive
  • Changes do not permanently alter your underlying data
  • You can adjust settings over time without fear of data loss

Flexible & Multi-Use

  • You can create different data views for the same connection, with very different sets of components (dimensions/metrics)
  • Create data views with different settings for visit timeout, attribution, etc.
  • Example: One data view with all dimensions set to Last Touch, another with First Touch — simultaneously, based on the same dataset

Foundation for Analysis

  • Workspace projects in Customer Journey Analytics are based on data views
  • Each data view is a specific configuration for how to interpret connection data

Data View Limits

| Limit | Value |

|---|---|

| Metrics per data view | Up to 5,000 |

| Dimensions per data view | Up to 5,000 |

What a Data View Does

A data view:

✅ Can be based on Customer Journey Analytics segments

✅ Can be applied to both historical and new data in a non-destructive manner

✅ Allows you to create one or many virtual views on top of a CJA connection for use by different business teams

✅ May be used to control access and curate different kinds of data for different users in CJA

✅ Provides powerful non-destructive transformation options for data coming into CJA through a connection

✅ Is based on report-time processing capabilities of CJA

✅ Allows users to create a custom definition for "session"

✅ Is applied at report runtime (after source data is written to the data lake and ingested into CJA)

✅ Allows for unlimited variables, although curation can limit which variables are exposed to users

✅ Allows for custom naming of Event, Session & Person containers

✅ Supports custom calendar options

What a Data View Does NOT Do

❌ Does not directly provide a means for combining report suites or datasets

Instead, datasets are combined in a CJA connection. The combined data from the connection is available for use in all data views based on that connection.

The Relationship: Connection → Data View → Workspace

```

Connection (combines multiple datasets)

↓

Data View (configures how to interpret the connection)

↓

Analysis Workspace (reports and analysis)

```

Creating a Data View

To create a data view:

1. In the Customer Journey Analytics UI, select [!UICONTROL Data views], optionally from [!UICONTROL Data management], in the top menu.

2. Select [!UICONTROL Create new data view].

3. In the [!UICONTROL Configure] step:

  • Select your connection from the [!UICONTROL Connection] list
  • Name and (optionally) describe your data view
  • Select [!UICONTROL Save and continue]

4. In the [!UICONTROL Components] step:

  • Add schema fields and/or standard components to the [!UICONTROL METRICS] or [!UICONTROL DIMENSIONS] boxes
  • Select [!UICONTROL Save and continue]

5. In the [!UICONTROL Settings] step:

  • Leave settings as desired
  • Select [!UICONTROL Save and finish]

Common Data View Configurations

| Use Case | Example |

|---|---|

| Different business teams | Marketing team data view vs. Product team data view — same connection, different metrics/dimensions exposed |

| Attribution models | Last Touch data view vs. First Touch data view — different attribution rules applied |

| Session definitions | Standard 30-min timeout vs. custom 15-min timeout for fast-paced interactions |

| Data governance | Public data view (all metrics visible) vs. Restricted data view (sensitive metrics hidden) |

Key Takeaway

Data views are the configuration layer between your raw connection data and your Analysis Workspace reports. They enable flexibility, governance, and business-specific customization without touching the underlying data.
