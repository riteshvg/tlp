Setting Up Identities in Adobe Journey Optimizer

Overview

Adobe Journey Optimizer does not maintain a separate identity store. Instead, it leverages Adobe Experience Platform's Identity Service and Real-Time Customer Profile as its shared data foundation. Setting up identities in AJO means configuring them within AEP, which AJO then reads at runtime.

Here is how identities work and how to set them up:

How Identities Work in AJO

AJO uses the Identity Graph (managed by AEP Identity Service) to stitch together a 360-degree view of a person across devices and channels. For example:

  • A CRMID represents a known person (e.g., logged-in user)
  • An ECID represents a web browser or mobile app session
  • The Identity Service links these together so that all prior behavioral data from a session can be associated to a logged-in user

Key Steps to Set Up Identities

1. Define Your Identity Namespaces in AEP

  • Navigate to Adobe Experience Platform → Identities
  • Use standard namespaces (e.g., `Email`, `Phone`, `ECID`) or create custom namespaces (e.g., `CRMID`, `LoyaltyID`) that match your business identifiers

2. Configure Your XDM Schemas

  • In AEP → Schemas, open or create the schema used by your AJO datasets
  • Mark the appropriate field as a Primary Identity (e.g., `CRMID` for profile records, `ECID` for event records)
  • Mark secondary identities as needed (e.g., `Email`)
  • Enable the schema for Real-Time Customer Profile

3. Enable Datasets for Profile

  • In AEP → Datasets, ensure datasets ingesting identity data are toggled on for Profile
  • This allows identity stitching to occur and merged profiles to be created

4. Ingest Identity Data

  • Send identity data via your data collection method:
  • Web SDK / Mobile SDK (recommended) — automatically collects ECID and can be configured to pass authenticated identifiers (CRMID, email) at login
  • Server-side API / Batch ingestion — for CRM or offline data

5. Verify Identity Stitching

Be aware of the following timing considerations:

  • Initial stitching (e.g., linking CRMID to ECID at login) can take 30 minutes to 4 hours to complete
  • After initial stitching, subsequent behavioral data sent with either identity is associated to the merged profile and available for personalization in AJO in near real-time (~1 minute)

How AJO Uses Identities at Runtime

Once identities are stitched in AEP:

| AJO Capability | How Identity Is Used |

|---|---|

| Journey conditions | AJO reads the merged profile to evaluate segment membership and attributes |

| Message personalization | Profile data linked via identity graph is used to personalize emails, push, SMS |

| Audience Qualification | Profiles are matched to audiences based on their unified identity |

| Offer decisioning | The merged profile is passed to the decisioning engine |

Important Considerations for Use Cases

  • Abandoned cart / re-engagement (30 min after abandonment): Be mindful that if a user has not previously logged in, initial identity stitching may not yet be complete, meaning the CRMID and ECID may not yet be linked in the identity graph
  • Post-login personalization: Once stitching is complete, all prior session data becomes available on the merged profile for real-time personalization

Summary

Setting up identities for AJO is fundamentally an AEP Identity Service configuration task:

1. Define identity namespaces

2. Configure XDM schemas with primary/secondary identities

3. Enable datasets for Real-Time Customer Profile

4. Ingest identity data via Web SDK or API

5. Allow time for initial stitching before relying on merged profiles in journeys
