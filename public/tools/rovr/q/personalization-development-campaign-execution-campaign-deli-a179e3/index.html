Adobe Target Technical Implementation Documentation

1. Campaign Delivery & Personalization

Adobe Target Overview & Activity Types

Adobe Target provides everything needed to tailor and personalize customer experiences to maximize revenue across web, mobile, and other digital channels. It supports multiple activity types for campaign delivery:

  • A/B Testing — Compare two or more experiences
  • Multivariate Testing (MVT) — Test combinations of offers across multiple locations
  • Experience Targeting (XT) — Deliver content to specific audiences based on rules
  • Automated Personalization (AP) — AI-powered 1-to-1 personalization
  • Auto-Target — ML-driven experience delivery based on visitor profiles
  • Recommendations — Automatically display relevant items to visitors

Target is licensed as either Target Standard (core testing and personalization) or Target Premium (adds Recommendations, Automated Personalization, advanced permissions, and more).

2. UI & Web Development — Visual Experience Composer (VEC)

The Visual Experience Composer (VEC) allows you to build and code offers visually without deep development overhead. For custom UI element development, Target also supports:

  • Form-Based Experience Composer — For non-visual, code-driven offer delivery (useful for email, kiosks, and custom DOM injection)
  • Custom Code Offers — Inject raw HTML, CSS, and JavaScript directly into offer locations
  • Flicker Management — A pre-hiding snippet must be added to prevent the default page from flashing before the personalized experience loads

The pre-hiding snippet is required in asynchronous tag deployments:

```javascript

;(function(win, doc, style, timeout) {

var STYLE_ID = 'at-body-style';

function getParent() { return doc.getElementsByTagName('head')[0]; }

function addStyle(parent, id, def) {

if (!parent) { return; }

var style = doc.createElement('style');

style.id = id;

style.innerHTML = def;

parent.insertBefore(style, parent.firstChild);

}

function removeStyle(parent, id) {

var style = doc.getElementById(id);

if (style) { parent.removeChild(style); }

}

addStyle(getParent(), STYLE_ID, style);

setTimeout(function() { removeStyle(getParent(), STYLE_ID); }, timeout);

}(window, document, "body {opacity: 0 !important}", 3000));

```

3. Multi-Platform Deployment

Web, Mobile & Responsive Properties

Adobe Target supports deployment across:

| Platform | Implementation Method |

|---|---|

| Web (Desktop/Laptop) | at.js or Web SDK (recommended) |

| Mobile Apps | Adobe Experience Platform Mobile SDK |

| Responsive Sites | Web SDK with responsive breakpoint logic |

| IoT / Kiosk / Voice | Server-Side SDK or Target APIs |

Key configuration requirement: All platforms route through a configured Datastream in Adobe Experience Platform, with Target enabled as a service on that datastream.

4. API & SDK Integrations

A. Adobe Experience Platform Web SDK (Recommended Modern Approach)

The Web SDK (`alloy.js`) is the current best-practice implementation path for Target on the web.

Learning objectives with Web SDK + Target:

  • Add the pre-hiding snippet to prevent flicker
  • Configure a datastream to enable Target functionality
  • Render Visual Experience Composer activities
  • Render Form Composer activities
  • Pass XDM data to Target and understand parameter mapping
  • Pass custom data including profile parameters and entity parameters
  • Validate a Target implementation
  • Separate personalization requests from analytics requests

XDM Mapping for Campaign Tracking:

```javascript

// XDM object mapping

marketing.trackingCode → Target campaign/tracking code

// Data object mapping (alternative)

data.__adobe.analytics.campaign

data.__adobe.analytics.v0

```

Datastream configuration prerequisite: Target must be enabled as a service within your AEP Datastream before any Web SDK calls will route to Target's edge network.

B. Adobe Launch (Tags) — Target v2 Extension

For tag-based deployments, use the Adobe Target v2 extension in Adobe Experience Platform Tags.

Prerequisites:

  • Access to Adobe Experience Platform Tags (included with Adobe CX Enterprise)
  • `manage_properties` permission granted by your org administrator

What you configure in the Target v2 extension:

1. Add the pre-hiding snippet for asynchronous tag embed codes

2. Add the Target v2 extension to your tag property

3. Fire the page load request (formerly called the global mbox)

4. Add parameters to the page load request:

  • mbox parameters — page-level contextual data
  • Profile parameters — visitor profile data (prefixed `profile.`)
  • Entity parameters — product/catalog data for Recommendations (prefixed `entity.`)

5. Fire the order confirmation request with required parameters (`orderId`, `orderTotal`, `productPurchasedId`)

6. Configure Library Header / Library Footer code for advanced customizations

7. Validate the implementation

> Note: Adobe Experience Platform Launch is now called Tags (client-side). Platform Launch Server Side is now Event Forwarding. Edge configurations are now Datastreams.

C. Server-Side / Backend SDKs (Java & .NET)

For server-side personalization, Target offers backend SDKs that enable:

  • Decisioning at the server layer — personalization logic executes before the page renders, eliminating flicker entirely
  • API-triggered delivery — external systems call Target APIs to retrieve offers and inject them into server-rendered responses
  • Hybrid implementations — combine client-side Web SDK for some activities with server-side SDK for others

Target's server-side approach is especially valuable for:

  • Authenticated environments (logged-in user personalization)
  • Mobile app backend personalization
  • Call center and IoT touchpoints

D. Target APIs

Adobe Target exposes a full REST API surface covering:

  • Delivery API — Retrieve personalized offers and experiences for any channel
  • Admin API — Create/manage activities, audiences, offers, and reports programmatically
  • Profile API — Read and write visitor profile attributes in real time
  • Reporting API — Pull activity performance data into external dashboards

5. Analytics for Target (A4T) — Reporting Integration

Adobe Analytics customers can select Analytics as the default reporting source during activity setup (A4T integration). This enables:

  • Selection of any Analytics success metric or audience segment retroactively applied to reporting
  • Extensive filtering and drill-down analysis of optimization results
  • Master Marketing Profile — unifies visitor IDs and data into a single actionable profile shared between Analytics and Target

Segments created in Adobe Analytics or Adobe Audience Manager can be used to target visitors directly in Target activities.

6. Audience Segmentation & Metrics Configuration

Target's audience and metrics configuration supports:

  • Built-in audience attributes — geography, device, browser, referrer, time of day
  • Custom profile attributes — passed via profile parameters or Profile API
  • Experience Platform audiences — AEP segments activated to Target via the Adobe Target destination in AEP

Activating AEP Segments to Target

The Adobe Target connection in AEP Destinations allows Real-Time CDP audiences to be used in Target activities:

  • Navigate to Destinations > Catalog > Personalization > Adobe Target
  • Configure the connection with your Target client code and datastream
  • Map audience segments for activation
  • Segments become available in Target's custom audience library

7. Quality Assurance

Target QA Capabilities

  • Activity QA URLs — Share preview links that force specific experiences without affecting live reporting
  • QA Mode — Sticky QA mode persists across pages using a cookie
  • Charles Proxy / Debugger validation — Inspect network calls to `tt.omtrdc.net` or `edge.adobedc.net`
  • Adobe Experience Platform Debugger — Browser extension that surfaces Target requests, mbox calls, and response tokens
  • Cross-browser testing — Validate experience rendering across Chrome, Safari, Firefox, and Edge, including mobile viewports

9. Team Enablement & Standardization

Coding Methodology & Frameworks

Best practices for standardizing Target implementations across teams:

| Area | Standard Practice |

|---|---|

| Offer templates | Reusable HTML/CSS/JS offer templates stored in Target's offer library |

| Selector strategy | CSS selectors over XPath; prefer `id` attributes over positional selectors |

| Profile script library | Standardized profile scripts for common segmentation logic |

| Workspace governance | Use Target Premium workspaces to separate business units and control permissions |

| Activity naming conventions | Consistent naming schema for activities, audiences, and offers |

| Documentation | Maintain implementation runbooks for each activity type and SDK pattern |
