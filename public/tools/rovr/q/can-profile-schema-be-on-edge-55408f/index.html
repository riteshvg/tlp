Can profile schema be on edge?

Based on the retrieved documentation context, here is what is covered regarding Profile Schema on Edge:

Yes, Profile Schema Can Be on Edge

The retrieved documentation confirms that XDM Individual Profile schemas can be projected to Edge, but with specific requirements and conditions:

Requirements for Profile Schema to Be on Edge

1. Schema Must Be Enabled for Real-Time Customer Profile

Before a profile schema can participate in Edge, it must first be enabled for Real-Time Customer Profile:

1. Navigate to [!UICONTROL Schemas] in the left navigation

2. Select the schema you want to enable

3. Under [!UICONTROL Schema Properties] on the right rail, toggle [!UICONTROL Profile] to ON

4. A confirmation popover appears — select [!UICONTROL Enable]

> ⚠️ Important: Once a schema is enabled for Profile and saved, it cannot be disabled. This is irreversible.

2. Schema Must Have a Primary Identity Field Defined

From the documentation:

> "In order to enable a schema for Profile, it must have a primary identity field defined."

  • For event data captured via Experience Platform SDKs, identity maps are typical
  • For profile attribute data, identity fields are labeled directly within the schema
  • Common primary identities used:
  • Experience Cloud ID (ECID)
  • CRM ID
  • Email

3. Active-On-Edge Merge Policy Must Be Configured

For profile schema data to be projected to Edge, an Active-On-Edge merge policy must be set up:

  • Navigate to AEP → Profiles → Merge Policies
  • Ensure the merge policy is set to Active-On-Edge
  • This determines which profile attributes from the schema are projected and available on Edge

4. Dataset Must Be Enabled for Profile

Even after enabling the schema, the dataset created from that schema must also be enabled for profile:

1. Navigate to [!UICONTROL Datasets] in AEP

2. Select the dataset built on your profile schema

3. Enable the Profile toggle on the dataset

4. Only then will data ingested into that dataset contribute to Real-Time Customer Profile and subsequently to Edge projection

What Gets Stored on Edge from Profile Schema

Once all above conditions are met, the Edge profile stores:

| Data Type | Description |

|---|---|

| Profile Attributes | Fields from XDM Individual Profile schema (name, preferences, consent, etc.) |

| Profile IDs | Primary and secondary identity values |

| Qualified Audience IDs | Segment memberships evaluated at Edge |

| `segmentMembership` | Namespace and status (`realized`, `exited`) for each qualified segment |

What Is NOT Supported

Based on the retrieved context:

  • Profile-enabled schemas cannot be disabled once saved — plan your schema carefully
  • Not all profile attributes may be projected to Edge — this is governed by the Active-On-Edge merge policy configuration
  • There is a propagation delay of 15–30 minutes from Hub to Edge after a profile is updated

Summary

| Requirement | Status |

|---|---|

| Schema must be enabled for Real-Time Customer Profile | ✅ Required |
