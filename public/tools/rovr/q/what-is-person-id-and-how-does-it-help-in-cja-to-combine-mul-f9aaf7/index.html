What is person ID and how does it help in CJA to combine multiple datasets?

Person ID in CJA

What is Person ID?

Person ID is a unique identifier that represents an individual customer across all your datasets in Customer Journey Analytics. It's the foundation for combining multiple datasets and enabling cross-channel customer journey analysis.

Core Concept

The Person ID column is the critical linking mechanism that allows CJA to:

  • Recognize when events belong to the same person across different datasets
  • Combine data from web, mobile, CRM, call center, and offline sources into a single person-centric view
  • Analyze complete customer journeys across channels and touchpoints

How Person ID Works Across Datasets

When you create a connection in CJA, you specify which field serves as the Person ID for each dataset:

Combined Dataset Merge

When multiple datasets are combined in a connection:

1. Different field names can represent the same person — For example:

  • Web analytics dataset uses `ecid` (Experience Cloud ID)
  • CRM dataset uses `customer_id`
  • Email dataset uses `email_address`

2. All merge into one Person ID column — Regardless of the original field names, CJA merges them into a single Person ID column in the combined dataset

3. Events are linked by person — All events with matching Person ID values are associated with the same person, even if they come from completely different data sources

Example: Multi-Channel Data Combination

| Original Dataset | Person ID Field | Value |

|---|---|---|

| Web analytics | `ecid` | `ABC123` |

| CRM | `customer_id` | `CUST456` |

| Call center | `caller_id` | `CALL789` |

After combining in CJA connection:

  • All three fields (if they represent the same person) are mapped to a single Person ID in the combined dataset
  • Events from all three sources can be analyzed together for that person

Requirements for Effective Person ID

For successful data combination, ensure:

✅ ID exists across all channels — The Person ID (or a related identifier) should be present in every dataset you want to combine

✅ ID is populated on each row — The Person ID value should be included on every event row of data

✅ Consistent format across sources — Use the same format, length, and hashing method across all datasets

  • Example: If one dataset hashes emails with SHA-256, others should too

✅ No PII required — You can use any ID, including hashed customer IDs (not personally identifiable information)

  • Example: Hash of a customer ID works just as well as the raw ID

Person ID vs. Persistent ID

Person ID

  • Represents an authenticated, known person (e.g., `customer_id`, `email`, `account_id`)
  • Not always available on every event (especially for anonymous sessions)
  • Used for identity stitching to connect authenticated and unauthenticated activities

Persistent ID

  • A device-level identifier (e.g., `cookie_id`, `ECID`, `AAID`)
  • Present on every event (both authenticated and unauthenticated sessions)
  • Ensures no data is lost even when Person ID is unavailable

Use Case: Cross-Channel Analysis

Scenario: Combine online and offline customer data

```

Web events: ecid = ABC123 (anonymous browsing)

CRM data: customer_id = CUST456 (known customer profile)

Call center: caller_id = CALL789 (customer support interaction)

```

With Person ID linking:

  • CJA recognizes CUST456, ABC123, and CALL789 all represent the same person
  • You can see: This customer browsed products → called support → completed purchase
  • Full journey visibility across all channels in a single Analysis Workspace report

Identity Stitching & Person ID

When datasets don't have a common Person ID on every event, identity stitching bridges the gap:

  • Field-based stitching uses event-level data to determine Person ID values
  • Graph-based stitching leverages the Experience Platform Identity Graph
  • Stitching rekeying ensures the Person ID is available on more events, improving data quality for person-level analysis

Key Takeaway

Person ID is the connective tissue that transforms isolated, siloed datasets into a unified, person-centric data model. Without it, CJA cannot effectively combine data sources or analyze cross-channel customer journeys.
