What is identityStitching and what are the different types of stitching methods available?

Identity Stitching in CJA

What is Identity Stitching?

Identity stitching (or simply "stitching") is a process that rekeys identities within a dataset's rows to ensure the desired person ID information is available on as many events as possible.

How It Works

Stitching looks at user data from both authenticated and unauthenticated sessions to determine a common person ID value that can be used across events. This rekeying resolves disparate records to a single person ID for analysis at the person level, rather than at the device or cookie level.

  • If a common person ID value can be determined, it's used for stitching
  • If a common person ID value cannot be determined, the persistent ID value is used instead

Goals of Stitching

Stitching elevates your event dataset's suitability for cross-channel analysis by allowing you to:

1. Create person-centric reports while not leaving out anonymous people

2. Connect multiple devices to a single person

3. Connect a person across channels

Where Stitching is Available

  • ✅ Person-based connections — Identity stitching is available
  • ❌ Account-based connections — Identity stitching is NOT available

Stitching Methods

There are two types of stitching methods available in CJA:

1. Field-Based Stitching (FBS)

How it works:

  • You specify an event dataset, a persistent ID (like a cookie), and a person ID (like an email)
  • FBS attempts to make the person ID information available for CJA data analysis on any anonymous events coming with a specific persistent ID
  • That information is retrieved from rows that have a person ID for that specific persistent ID
  • If person ID info cannot be retrieved for an event, the persistent ID is used instead for that unstitched event

Use case:

  • When using CJA as a standalone solution without access to the Experience Platform Identity Service
  • When you don't want to use the available identity graph

2. Graph-Based Stitching (GBS)

How it works:

  • Uses the Experience Platform Identity Graph to resolve identities
  • Leverages the identity relationships already built in Experience Platform
  • Follows last-auth attribution — attributes all unknown activity from a shared device to the user who last authenticated
  • The Experience Platform Identity Service builds the graph based on last-auth attribution, which is then used in graph-based stitching

Use case:

  • When you have access to the Experience Platform Identity Service
  • When you want to leverage your existing identity graph setup
  • For more sophisticated identity resolution across multiple identity namespaces

Attribution Methods Within Stitching

Last-Auth Attribution

Last-auth attributes all unknown activity from a shared device to the user who last authenticated.

Example:

| Timestamp | Page name | Device ID | Email | Stitched ID |

|---|---|---|---|---|

| 2023-05-12 12:01 | Home page | `1234` | | `cassidy@a.com`|

| 2023-05-12 12:02 | Product page | `1234` | |`cassidy@a.com` |

| 2023-05-12 12:03 | Order success | `1234` | `ryan@a.com` | `cassidy@a.com` |

| 2023-05-12 12:07 | Product page | `1234` | | `cassidy@a.com` |

| 2023-05-12 12:08 | Order success | `1234` | `cassidy@a.com` | `cassidy@a.com` |

| 2023-05-13 11:08 | Home page | `1234` | | `cassidy@a.com` |

In this example, even though `ryan@a.com` authenticated on 5/12 at 12:03, subsequent events are attributed to `cassidy@a.com` because she was the last to authenticate on that device.

Device-Split Attribution

Stitching in Connections: Live Pass

Stitching makes a minimum of two passes on data:

Live Stitching:

  • Attempts to stitch each hit (event) as it comes in
  • Uses the persistent ID to look up the person ID for the selected namespace by querying the identity graph
  • If the person ID is available from the lookup, it's immediately stitched
